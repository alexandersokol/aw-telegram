# Endtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a locally evaluated daily endtime with Telegram control and confirmed reached-time alerts, change overlays to newest-due-wins, and raise the active caregiver limit from two to ten.

**Architecture:** Extend strict active v2 settings with endtime state and a dedicated generation, then evaluate warnings and overlays in the offline Windows scheduler. A confirmed presentation receipt flows through authenticated device sync into the existing transactional event/outbox system; suppression is rechecked before sending. Existing pairing, authorization, and fan-out paths use one shared ten-caregiver bound.

**Tech Stack:** Python 3.12, PySide6, SQLite, pytest/pytest-qt; TypeScript, Node.js 22, Firebase Admin/Firestore, grammY, Vitest and Firebase Emulator; generated JSON Schema draft-07 contracts.

**Spec:** [../specs/2026-10-29-endtime-design.md](../specs/2026-10-29-endtime-design.md)

## Global Constraints

- Use `Europe/Kyiv`; endtime accepts exact zero-padded `00:15` through `23:59` only.
- New settings default to `endtimeEnabled=false`, `endtimeLocalTime="21:00"`, and `endtimeGeneration=0`.
- Advance `endtimeGeneration` only when the effective enabled/time pair changes; unrelated settings and idempotent no-ops do not advance it.
- Preserve archived v1. Active v2 remains strict on the wire; compatibility exists only in persisted-state migration.
- Warning cards are laptop-only at 15/10/5 minutes. Telegram alerting requires confirmed overlay presentation.
- Repeats from one date/generation alert once; a deliberate later same-day generation may alert again.
- Free use and Clear all silence local behavior and cancel undelivered endtime alerts retroactively.
- A first eligible evaluation strictly after endtime skips the date; equality is due.
- Newest due overlay replaces the visible overlay. Replacement terminates a manual repeat family; endtime policy schedules a new occurrence one minute later.
- Support at most ten active authorized caregivers per laptop; reports remain private and shared coordination excludes only the issuer.

## Review Focus

- Restart/resume strictly after endtime must skip today rather than replay it; pin in Task 6 `test_resume_after_endtime_skips_date`.
- Free use/Clear all racing a queued or leased endtime event must prevent Telegram send; pin in Task 4 `suppression cancels queued and leased endtime delivery`.
- An unrelated settings edit must not create another generation, while an intentional later same-day endtime edit may alert again; pin in Tasks 3 and 4.
- Alternating manual/endtime occurrences must not resurrect replaced overlays or duplicate one generation's Telegram receipt; pin in Task 6 `test_newest_overlay_wins_without_resurrection`.
- Ten-caregiver fan-out must still recheck each generation-bound recipient and leave the eleventh pairing key unused; pin in Tasks 2 and 4.

### Task 4: Process confirmed endtime receipts and suppress Telegram delivery

Checkpoint (2026-10-29): implemented locally, not yet independently reviewed.
Receipts validate against the retained generation entry (enabled, same time, a
settings revision inside that generation's window, not after server time). An
unretained date or a suppressed date is acknowledged without an alert. Event identity
is `device/date/generation`; outbox rows carry `policy`. Free use, Clear all and the
Clear-all settings path cancel up to 100 pending/uncertain rows for the date in their
transaction. The worker rechecks suppression in the lease and again after recipient
authorization, immediately before Telegram. Receipts beyond a 200-write planning budget
stay unacknowledged so the companion resends them. `tasks.ts` and `outbox.test.ts`
needed no change; the receipt/suppression cases live in `endtime.test.ts`. Bot suite:
138 passed; emulator auth/pairing/rules/sync/delivery: 48 passed (JBR 25); build and
