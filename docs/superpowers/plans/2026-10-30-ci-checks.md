# CI Checks (Task 11a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every push and pull request runs the bot's and the companion's existing checks on
GitHub Actions.

**Architecture:** one workflow, `.github/workflows/ci.yml`, with two independent jobs:
- `bot` on Ubuntu: Node 22, Java 21, the pinned Firebase CLI from `bot/node_modules`;
- `companion` on Windows: Python 3.12.6 and `requirements.lock`.

No secrets, no deploys, read-only permissions.

**Tech Stack:** GitHub Actions (`actions/checkout@v4`, `actions/setup-node@v4`,
`actions/setup-java@v4`, `actions/setup-python@v5`, `actions/cache@v4`), npm, vitest, the
Firestore emulator, pytest with pytest-qt.

Spec: [2026-10-30-ci-release-readme-design.md](../specs/2026-10-30-ci-release-readme-design.md),
section 1. Task: implementation-plan.md, 11a.

## Global Constraints

- Triggers: `push` (all branches) and `pull_request`. Permissions: `contents: read`. No secrets.
- Bot checks, in this order, from `bot/`:
  - `npm ci`
  - `npm test`
  - `npm run build`
  - `npm run check:bundle`
  - `npm run test:emulator -- auth pairing rules sync delivery purge cleanup`
- Bot toolchain: Node 22 (`engines: 22.x`) and Java 21 for the Firestore emulator.
- Companion checks, from `companion/`:
  - `python tools/licenses.py check`
  - `python -m pytest -q`, without `QT_QPA_PLATFORM=offscreen`: some UI tests need a real window
- Companion toolchain: Python 3.12.6 on Windows. Install `requirements.lock` into a virtual
  environment. The tests use `pythonpath = ["src"]` (pyproject), so no editable install.
- The python.org-installer requirement applies to the PyInstaller build only (11b), not to these
  tests.
- Nothing is pushed to GitHub without the owner's go-ahead in chat.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

### Task 1: The workflow

**Files:**
- Create: `.github/workflows/ci.yml`

**Interfaces:**
- Produces: workflow `CI` with job ids `bot` and `companion`. The 11h README badge points at
  `actions/workflows/ci.yml`, and 11b's release job repeats the companion steps.

- [ ] **Step 1: Write the workflow**

```yaml
name: CI

on:
  push:
  pull_request:

permissions:
  contents: read

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  bot:
    name: Bot (unit, build, emulator)
    runs-on: ubuntu-latest
    timeout-minutes: 25
    defaults:
      run:
        working-directory: bot
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
          cache-dependency-path: bot/package-lock.json
      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '21'
      - name: Install
        run: npm ci
      - name: Unit tests
        run: npm test
      - name: Build and typecheck
        run: npm run build
      - name: Bundle check
        run: npm run check:bundle
      - name: Cache the Firestore emulator
        uses: actions/cache@v4
        with:
          path: .firebase/emulators
          key: firestore-emulator-${{ hashFiles('bot/package-lock.json') }}
      - name: Emulator suites
        run: npm run test:emulator -- auth pairing rules sync delivery purge cleanup

  companion:
    name: Companion (licenses, tests)
    runs-on: windows-latest
    timeout-minutes: 25
    defaults:
      run:
        working-directory: companion
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.12.6'
          cache: pip
          cache-dependency-path: companion/requirements.lock
      - name: Install
        run: |
          python -m venv .venv
          .venv\Scripts\python.exe -m pip install --upgrade pip
          .venv\Scripts\python.exe -m pip install -r requirements.lock
      - name: License texts
        run: .venv\Scripts\python.exe tools\licenses.py check
      - name: Tests
        run: .venv\Scripts\python.exe -m pytest -q
```

`scripts/test-emulator.mjs` stores the emulator under `<repo>/.firebase/emulators`, which is the
cached path. Its environment guard refuses `GOOGLE_APPLICATION_CREDENTIALS` and non-demo
projects, and the runner sets neither.
